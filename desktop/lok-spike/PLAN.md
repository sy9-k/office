# SK Hub Office（デスクトップ版）: LibreOffice ベースの Doc 計画

## 決まったこと
- **ファイルの形式**: デスクトップ版の Doc の正は `.docx`。今の `.skdoc`（JSON）は読み込みだけ残す。
- **独自のグラフ・デザインテーマ**: いったんやめる。LibreOffice の機能に任せる。
- **Web 版**: 今のまま変えない。
- **対象**: まず Doc だけ。Sheet・Slide は Doc が安定してから。

## ゴール（この計画の完了条件）
デスクトップ版で、Doc の画面の中で次が完結すること。
1. 新規作成・既存の docx を開く
2. 文字入力（日本語 IME を含む）・改行・削除・移動・選択
3. 太字・斜体・下線・元に戻す・やり直す
4. 保存（同じファイルに上書き）と、閉じてから開き直したときの見た目の一致
5. 表・脚注・コメント・図・リストが、保存で消えないこと（確認済み）

## 今の状態（出発点）
- `desktop/lok-spike/lok_server.c`: LibreOffice（LOKit）を読み込む HTTP サーバー（描画・入力・選択・保存）
- `desktop/lok-spike/web/index.html`: 描画と入力の画面（今はパネルとして重ねている）
- `shared/doc.js`（2385 行）: 今の HTML 編集の Doc。描画・入力・リボン・書き出し・読み込みをすべて持つ
- `shared/office.js`: 画面の枠（ハブ・保存・ファイルの開閉）
- `shared/store.js`: ファイルの保存（JSON の `.skdoc`）

## フェーズ

### フェーズ 1: Doc の編集本体を LibreOffice にする（デスクトップ版だけ）
- 新規 `shared/doc-lok.js`: `web/index.html` の描画・入力・選択・カーソルの処理を、パネルではなく Doc の画面の中の部品として作り直す
- `shared/doc.js`: デスクトップ版では、`contenteditable` の本文の代わりに `doc-lok.js` を使う。ハブ・リボン・メニュー・ステータスバーはそのまま
- 今のパネル（「LibreOffice で表示」）は、フェーズ 1 の完了で外す
- 完了の条件: 開く・編集・書式・保存・開き直し が Doc の画面の中で動く

### フェーズ 2: ファイルの形式を docx に一本化（デスクトップ版）
- 新規の Doc は `名前.docx` として保存（LibreOffice が書いたものをそのまま保存）
- 既存の `.skdoc`（JSON）は、開くときに一度 docx に変換して、新しい形式で保存し直す（元は残す）
- Google ドライブ保存も docx のバイト列で行う（既存の保存の仕組みを流用）
- 完了の条件: 作って・閉じて・開いて、同じ見た目。`.skdoc` の既存ファイルが開けて、変換後も壊れない

### フェーズ 3: 書式の命令の経路
- 今は Ctrl＋文字のキーで太字・斜体・下線・元に戻す・やり直すを送っている（動作を確認済み）
- リボンの残りの命令（フォント・大きさ・色・段落・表・画像など）を、どの経路で送るかを決める
  - 候補 A: キーの組み合わせで足せるものは足す
  - 候補 B: LibreOffice の UNO の API を直接使う経路を調べる（`postUnoCommand` は効かなかった）
- 完了の条件: MVP のリボンの命令が、すべて動くか、非表示になっている

### フェーズ 4: 独自機能の整理（やめる・LibreOffice に任せる）
| 機能 | 扱い |
|---|---|
| 独自のグラフ（SVG） | やめる（LibreOffice のグラフを使う） |
| デザインのテーマ（`design:`） | やめる |
| 用紙（サイズ・余白・縦横・段組み） | フェーズ 4 で LibreOffice の設定に任せる。最初は非表示 |
| ヘッダー・フッター | LibreOffice の機能に任せる |
| ナビゲーション（見出し一覧） | 後回し。LibreOffice の機能を調べる |
| コメント | LibreOffice の機能に任せる。操作の経路は後で決める |
| 目次・脚注 | LibreOffice の機能に任せる。挿入の経路は後で決める |
| 書式のコピー・検索と置換 | 後回し |
| PDF の書き出し・印刷 | 後で LibreOffice の書き出しに切りかえる |
| HTML・Markdown・テキストの書き出し | 後回し（docx 以外は当面残さない） |

### フェーズ 5: 配布できる形にする
- `lok_server.exe` と LibreOffice の扱い（インストーラーに同梱するか、別に入れてもらうか）を決める
- 異常終了したときの再起動、起動に失敗したときの表示、アプリを閉じたときの後始末
- LibreOffice（MPL 2.0）の表示と、LOKit のヘッダーのライセンス表示
- 同じ文書を二つのウィンドウで開いたときの扱い

## リスク
- **書式の命令の経路**（フェーズ 3）: 今のところ Ctrl＋キーの代用しかない。リボンの全部を代用で足すのは無理があるかもしれない
- **Windows の IME（TSF）の実機での動き**: まだ確かめていない。変換候補ウィンドウの位置も未対応
- **描画の速さ**: タイル全体を描き直しているので、長い文書で遅くなる可能性
- **LOKit の仕様の変化**: LibreOffice のバージョンを固定する必要がある（今は 26.8.1.1）

## 方針の変更（2026-10-29）: 二つに分ける
- **完全 Web ベースのデスクトップ版**: 今の Web 版のコード（`contenteditable` の Doc、HTML の編集）をそのまま使う。LibreOffice は使わない
- **完全 LibreOffice ベースのデスクトップ版**: 文書の処理は LibreOffice（LOKit）。画面（リボン、ファイルの画面、ハブ）は HTML で作る。Doc の本文は、フェーズ 1 の `shared/doc-lok.js` を使う
- 今の作業（フェーズ 1）は、LibreOffice 版だけに入るようにする。Web 版では、今の HTML の編集を変えない
- 分け方（ブランチ・ビルドの設定・アプリの名前）は、まだ決めていない
- 「完全 LibreOffice」の画面を LibreOffice 自身の UI（VCL）にする案は、規模が大きいので、今は採らない（必要が出たら、フォークの一部改造を検討）
